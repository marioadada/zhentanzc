## 一、用户提的三个问题，逐个结论

### 问题 ①「网页好像只有前端，搜索起来不可用」→ 确诊为真问题，已修

**诊断结果（不是主观判断，是实测）**：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 原文可切分条款 | 243 条 | 249 条（索引全覆盖） |
| 已结构化入库 | 42 条（**17%**） | 53 条 |
| 检索方式 | 关键词表匹配（10 类判定式硬编码） | **BM25 全文检索 + 领域词典** |
| 14 个自然问题未匹配数 | **5 个（36% 失败）** | **0 个** |
| Top-3 召回率 | — | **91%** |
| Top-1 精确率 | — | **73%** |

**根因**：上一版只把「人工挑选的 42 条」结构化入库，剩下 83% 的原文条款**根本检索不到**。评委输入任何自由问法都可能落空。

**修法（三层）**：

1. **全量切条款**（`pipeline/build_search_index.py`）
   - 规范性文件按「第X条」切，办事指南按「申请材料/办理依据/申请条件/办理流程」段落切
   - 243 → 249 条，全部进倒排索引
   - 外部法律引用（`[法律]`/`[行政法规]`）标记为 `reference` 并降权 0.45 倍，避免"社保卡怎么申领"命中《劳动法》

2. **中文分词加领域词典**（100+ 词）
   - 没有词典时「我在厦门没有户口能参保吗」命不中含「户籍」的条款
   - 加词典后 Top-1 精确率 **58% → 73%**

3. **制度域用位置判断而非关键词**
   - 厦府规〔2022〕12号 是职工+居民两套细则合并本，条款号撞车
   - 关键词判断只能覆盖 34%，**位置判断（用条款在原文中的偏移落到域区间）覆盖 85%**
   - 未识别占比 **66% → 15%**

4. **路由改为「关键词高置信优先 + 检索兜底」**
   - 纯 BM25 优先会导致「居民医保一年交多少钱」被通用条款抢走（回归过一次，被断言 D1/D2 抓到）
   - 关键词得分 ≥2 时以关键词为准，检索只补条款

### 问题 ②「该补充的补充」→ 三个数据缺口全部补齐

| 缺口 | 补齐内容 | 依据 |
|---|---|---|
| **参保承诺制** | 职工医保参保范围与灵活就业（4 类人群）、外国人参照参保、退休资格 | 厦府规〔2022〕12号 第四条、第八十六条、第三十四条 |
| **跨险种转移接续** | 转移接续、年限合并条件（未中断或中断≤3个月补缴到账可合并）、视同缴费年限、居民医保年限不计入职工医保 | 同文件第三十二、三十三条 + 医保局官方提示 |
| **居民医保集中期与等待期** | 固定等待期 3 个月、变动等待期每断保 1 年加 1 个月、连续参保满 4 年每年提高 3000 元、退费政策 | 医保局《待遇等待期？两大激励？》官方答疑 |

**顺带挖到的额外收获**（元宝搜索命中）：
- 职工医保退休累计年限 **男 25 年 / 女 20 年**、本市实际缴费满 10 年
- 转移接续年限合并的**具体条件**（之前只有"按规定办理"这种空话）
- 居民医保跨统筹地区不再重复参保 + 退费时点规则
- 长护险居民长护险建制首年减半征收 0.15%、个人与财政 1:1 分担

**新增 2 个判定式**：`insurance_transfer`（转移接续）、`resident_wait_period_calc`（等待期计算）→ 判定式总数 **10 → 12**
**新增 1 个计算器**：`resident_wait_calc`（3 + 断保年数×1 个月）

### 问题 ③「按 Vercel design 规范优化各端名称」→ 设计师出规范，前端落地

**设计师产出**（`web/naming-spec.json`，176 条规范，覆盖率 100%）：
- 依据：Vercel Web Interface Guidelines + Geist Design System + design.md
- 每条改名都给了**指向具体原则的理由**，不是"更好听"
- 提供 canonicalTerms（术语唯一性）+ forbiddenTerms（禁词表）

**关键改名**：

| 原文案 | 新文案 | 依据 |
|---|---|---|
| 问题查证 | **政策查证** | 标题要说清动作落点，不描述输入物 |
| 我的画像 | **个人画像** | 术语唯一 |
| 制度对比 | **方案对比** | 与"方案"术语统一 |
| 开始查证 | **查证政策问题** | 按钮用动词，贴近用户动作 |
| 补齐条件再算 | **补齐条件后重算** | 动词优先 |
| 去官方办理入口 | **查看官方办事信息** | 避免"入口"歧义 |
| 这条错了 | **反馈判定问题** | 术语统一为"判定" |
| 完善画像 | **填写你的情况** | 动词开头 |

**安全阀（我加的，防止规范破坏产品核心承诺）**：
1. **七态判定语义保护**——「条件待核验」「时点不适用」等只允许改分隔符，不允许改词。脚本内置拦截
2. **禁词表检查**——「结论」除「审批结论」外一律改「判定」；「核验」只允许出现在「条件待核验」内。实施后 **0 处越界**
3. **占位符保护**——动态拼接文案（如 `一次可办（'+n+' 项联办）`）不能按字面替换，改为前缀替换
4. **幂等入口**（`apply_naming_all.py`）——每次从基线重建，避免重复执行污染页面

## 二、顺带做的 Vercel Geist 规范化

| 项 | 修复前 | 修复后 |
|---|---|---|
| 硬编码色值 | **49 种** | **0 种**（45 个 `--geist-*` Token） |
| emoji 作功能图标 | 3 处（⚠ ×2、✓ ×1） | **0**（内联 SVG，16px / stroke 1.5 / currentColor） |
| 字符箭头当图标 | 2 处（↗） | **0**（SVG external 图标） |
| 紫粉渐变 | 0 | 0（保持） |
| 弹跳缓动 | 0 | 0（保持） |

**Token 结构**（按 Geist 色板分层）：
```
--geist-bg / bg-1 / bg-2 / bg-3      背景层级
--geist-fg / fg-2 / fg-3 / fg-muted   文字层级
--geist-border / border-2/3/4        边框层级
--geist-accent / accent-hover / …     强调色（含 ring/soft/line 系列）
--geist-success / warning / error     语义色（各含 fg/bg/line/dot）
```

**设计规范检查已固化为断言**（Python 端 W 组 6 条 + 页面端 N 组 6 条），任何回退都会被 CI 拦住。

## 三、这一轮抓到的自身缺陷（都是"不做真机测试绝对发现不了"的那类）

| 缺陷 | 后果 | 修法 |
|---|---|---|
| **`ROUTES` 里 `caseId` 写成 `case_id`** | **所有查询静默返回空** —— 页面能开、无报错、就是没结果 | 修字段名 |
| 阶梯参数当二元组读 `value[0]/value[1]` | 对比表与连续参保计算器抛 `th[1].map is not a function` | 改两个独立参数 |
| 引擎未导出 `cases` | 画像页产出空白 | 补导出 |
| **滑块把费率当倍数** | 显示 95000 元而非 950 元 —— **用户会看到错数字** | 改 `× rate/100`，费率从参数表取 |
| 条件不全时不跑计算器 | 失业保险金明明能算月标准却不显示 | 条件不全也跑，能算的先给 |
| `district` 误设必填 | 浏览器校验拦截提交，画像点了没反应 | 改可选 |
| 时点用 UTC | 本地早上 8 点前显示昨天 | 改本地日期 |
| BM25 索引缺 `doc_len` | 页面检索直接崩溃 | 补字段（Python 端打包时漏了） |
| **渲染型源文本被 44 字符列表页覆盖** | 养老费率参数整条消失，3 条断言变红 | 渲染结果必须落标准 `.txt`；加 X13 断言防回归 |
| **制度域靠关键词猜 → 标反** | 「医保关系转移接续」标成居民域、「居民大病保险」标成职工域（**同为第三十二条**） | 域以 REGIME 标记为准，不猜；加 Y 组 8 条断言 |
| 规范里「（保持不变）」被当目标文案 | 页面出现满屏"（保持不变）" | 脚本识别标记；改用幂等入口 |
| 外链箭头 SVG 化时替换进了字符串字面量 | 页面判定卡整个不渲染 | 修拼接层级 |

其中三个最值得记：
- **`caseId` 拼错** —— 静默失败，无报错。这类 bug 只有真机点一遍才会暴露
- **滑块费率当倍数** —— 显示错数字，比崩溃更危险（崩溃用户会重试，错数字用户会照着交钱）
- **制度域标反** —— 引用看着完整、点开也有原文，但归属错了。**这正是"原文可回溯"不够、必须加"域标识"的原因**

## 六、团队协作中发现的三类问题（比技术问题更值得记）

这一轮用了 MVP开发专家团流程（设计师 + 前端并行），暴露了三类**协作层面**的问题，都是纯靠自己做不会撞到的：

### 1. 归属模糊会冻结后续质疑

设计师问：`pipeline/` 那批改动是谁写的？如果被默认成"设计师写的、审美已定稿"，后面就没人再质疑它的措辞与结构。

**事实**：规范是设计师的，实现是我的。已把脚本头部改成"规范数据来源：设计师交付；实现与门禁：项目总监"。

**教训**：交付物要标明**来源**，而不仅是**位置**。同一个文件里"谁写的"和"谁维护"是两件事。

### 2. 共享工具的默认行为可能破坏协作者

`apply_naming_all.py` 原本从基线整体重建页面 —— 这是"让结果可复现"的直觉做法，但**会静默吞掉别人的改动**，且无 git 可回滚。

改成增量应用后：文本替换天然幂等，基线降级为只读对照快照。

**教训**：共享脚本的默认行为必须假设"有人在并行改同一个文件"。可复现性靠幂等，不靠覆盖。

### 3. 同一份规范里的"看起来对"的条目也会自我重复

设计师规范里 `from='厦门社保'` → `to='厦门社保缴费状态'`。页面原文恰好是"厦门社保缴费状态"，跑一次变"…缴费状态缴费状态"，跑三次变五遍。

我只做了干跑（看输出对不对），**没做连跑比对哈希**，所以没发现。是被"幂等性实测"抓出来的。

已加两道防护 + 6 条断言（Z 组）。

**教训**：验证一个会改文件的脚本，"跑一次看输出"不够，必须"连跑 N 次比对哈希"。

### 附：设计师给的两条专业红线

| 红线 | 理由 |
|---|---|
| 承诺制不得写进职工医保参保条件组 | 厦府规〔2022〕12号第四条里**没有"承诺制"三个字**，它只指向养老保险参保登记的税务口径。写进条件组等于伪造依据，比措辞不准严重得多 |
| 「待人工」必须保留，不能改「待裁决」 | 它与「条件待核验」是两类完全不同的待办：等你补条件 vs 等人工裁决两个文件打架。改成「待裁决」会与「已裁决」语义撞车 |

这两条比我最初的判断更准，已写入实现注释与断言。
