**字段说明**

| 字段 | 作用 | 必填 |
|---|---|---|
| `layer` | 证据层级 L1–L5，决定可否作为结论依据 | ✅ |
| `raw_sha256` / `text_sha256` | 快照指纹，官方改文可被发现 | ✅ |
| `valid_from` / `valid_to` | 生效区间，判定时按时点选版本 | ✅ |
| `supersedes` / `superseded_by` | 沿革链，双向 | ✅ |
| `status` | `active` / `partially_superseded` / `superseded` / `expired` | ✅ |
| `version_notes` | 替代关系**及原因**（不是只存 ID） | ✅ |

| `needs_ocr` | 该源为扫描件、文本经 OCR 得出，可信度需标注 | — |

### 3.4 条件 Condition

```json
{
  "field": "residence_permit_xiamen",
  "op": "eq",
  "value": true,
  "label": "持本市有效居住证",
  "why": "户籍限制自2023-01-01起已全面放开",

```

`alternative` 表达"或"关系——户籍 **或** 居住证，满足其一即可。引擎求值时按 OR 组处理。

## 四、判定引擎

### 4.1 判定结果七态

| 枚举 | 中文 | 含义 | 展示要求 |
|---|---|---|---|
| `ELIGIBLE` | 符合 | 全部硬条件已确认且满足 | 必须附引用 + 下一步 |
| `NOT_ELIGIBLE` | 不符合 | 至少一条硬条件已确认且不满足 | 必须列出**哪条**不满足 |
| `NEEDS_VERIFY` | 条件待核验 | 存在未知硬条件 | 必须列出缺什么 + 为什么问 |
| `TIME_NOT_APPLICABLE` | 时点不适用 | 结论只适用于另一时点 | 必须给出适用时点区间 |
| `CONFLICT_RESOLVED` | 来源冲突（已裁决） | 来源冲突但规则表能裁决 | 必须给出裁决依据 |
| `CONFLICT_PENDING` | 来源冲突（待人工） | 规则表无法裁决 | 必须并列两方原文，不得自行择一 |
| `NO_EVIDENCE` | 未查到可靠依据 | 一手源未命中 | 必须给官方自查入口，不得空白 |

### 4.2 判定流程

```
问题 + 画像 + as_of
   │
   ├─ 1. 意图路由         社保决策 / 查证 / 画像推荐 / 条件办理
   ├─ 2. 编译判定式        取 cases.json 中匹配的 case
   ├─ 3. 时点分层检查      as_of 落在哪个版本区间 → 命中哪个版本
   │      └─ 未命中任何区间 → TIME_NOT_APPLICABLE
   ├─ 4. 条件求值          逐条 evaluate_condition → pass/fail/unknown
   │      ├─ 有 unknown → NEEDS_VERIFY
   │      ├─ 有 fail    → NOT_ELIGIBLE
   │      └─ 全 pass    → ELIGIBLE
   ├─ 5. 冲突裁决          两源同时命中 → CONFLICT_RULES 依次尝试
   ├─ 6. 计算器附加        参数表取值 → 纯函数计算
   └─ 7. 输出              判定 + 引用 + 缺失条件 + 下一步
```

### 4.3 冲突裁决规则表（按优先级）

| 序 | 规则 ID | 名称 | 判据 | 实现 |
|---|---|---|---|---|
| 1 | `later_file_wins` | 后法优于前法 | 新文件 `valid_from` 更晚 | 可测函数 |
| 2 | `higher_level_wins` | 上位优于下位 | 省级(3) > 市级(2) > 区级(1) | 可测函数 |
| 3 | `province_pooling_wins` | 省级统筹优先于市级条例 | 文件明文"暂停执行"或"以本通知为准" | 可测函数 |
| 4 | `special_over_general` | 特别规定优于一般规定 | 针对特定人群的专门规定 | 可测函数 |

全部无法命中 → `CONFLICT_PENDING`，并列两方条款原文。

**已验证的真实裁决**（厦府规〔2025〕7号）：明文"暂停执行《厦门经济特区失业保险条例》第十七条第一款、第十八条…按'省条例'执行"，命中规则 3 → `CONFLICT_RESOLVED`，裁决依据为文件自身明文。

### 4.4 三个计算器（纯函数，参数全部来自参数表）

| 计算器 | 输入 | 输出 | 依据条款 |
|---|---|---|---|
| `flexible_medical_monthly` | 参保时间、险种、已选基数 | 月缴费额 = 基数 × 费率；未选基数则给可选区间 | 2026 年度公告 + 闽人社文〔2026〕13号 |
| `continuity_tier` | 连续参保月数、是否 3 个月内补缴 | 大病保险待遇档位（50/75/100%）+ 断缴提示 | 厦府规〔2022〕12号 第四十七条 + 医保局访谈 |
| `unemployment_benefit` | 累计缴费月数、本市最低工资 | 月失业保险金 = 最低工资 × 90%；可领月数 = 年数 × 2，上限 24 | 厦府规〔2025〕7号 |

**代码中零硬编码**：断言 G1 扫描引擎逻辑里的 `0.0x` 字面量 → 当前通过。

### 4.5 时点分层实现

每个 case 可声明 `versions` 数组，每项带 `as_of_range`：

```json
"versions": [
  {"as_of_range": ["0000-01-01", "2026-02-28"], "verdict": "NOT_ELIGIBLE",
   "basis": "闽医保〔2019〕126号 与 厦府规〔2022〕12号 均明确灵活就业人员不参加生育保险"},
  {"as_of_range": ["2026-03-01", "9999-12-31"], "verdict": "ELIGIBLE",
   "basis": "闽医保〔2026〕13号 将参加职工医保的灵活就业人员纳入生育保险覆盖范围"}
]
```

判定命中当前区间后，**同时输出另一时点的结论**（`detail.other_timepoints`），用户能看到"以前是这样，现在是这样"。

### 6.2 引擎实测输出（28 岁默认画像，as_of 2026-10-24）

```
[条件待核验] 我能以灵活就业人员身份参加厦门职工医保吗？
  缺失: 未在用人单位参加职工医保
  ※ 户籍条件走"或"分支：本市户籍=false 时转向居住证，居住证也未知 → 记为缺失

[符合] 灵活就业人员能参加生育保险、享受生育津贴吗？
  其他时点 [0000-01-01~2026-02-28] -> 不符合

[符合] 我灵活就业参加职工医保，每月要交多少钱？
  计算待输入: chosen_base  可选区间 {'min': 4579, 'max': 22893}

[条件待核验] 断缴后我的医保待遇会怎么变？
  缺失: 连续参保月数, 中断后是否在3个月内补缴

[条件待核验] 我能领多少失业保险金、能领多久？
  缺失: 失业前累计缴费月数, 是否非因本人意愿中断就业
```

**注意第一行**：户籍=false 且居住证未知时，引擎没有直接判定"不符合"，而是把居住证列为缺失条件——这正是"不能仅凭户籍/年龄推断资格"的实现体现。
